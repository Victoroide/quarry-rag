# Routing calibration

With the evidence routing policy, a profile must match the embedding provider, configured model and vector dimensions. A supplied file replaces the embedded profile set. Its root contains `schema_version: 1` and a non-empty `profiles` array. Each entry contains a version string, a `provider` (`bedrock`, `openai` or `offline`), the configured `model`, integer `dimensions`, `metric: "cosine"` and a numeric `margin`. Use model `fake` with the offline provider. An invalid file fails startup when evidence routing is active.

OpenAI-compatible profiles also need `endpoint_sha256`, the lowercase hexadecimal SHA-256 of the configured base endpoint after removing trailing slashes, and `model_revision`, the operator's immutable model revision label. Set `ROUTING_EMBEDDING_REVISION` to the same revision. If either deployment identifier is missing or differs, automatic evidence routing uses `GLOBAL`. Include each full profile identity once.

The [published replay profiles](../internal/config/routing_profiles.json) use the replay-only provider and the versioned `quarry-char3-bow-v1` model at 256 and 1024 dimensions. Deployed models need a matching operator-supplied profile for automatic `LOCAL`. Fit it on representative scoped documents. A margin override applies only to a matching profile.

The [replay corpus](../internal/pipeline/testdata/routing_eval.json) pins the document text, stored 120-character previews, query pairs, fact labels, chunk settings and search limits. Tests check the raw manifest digest and golden embedding outputs. A model change requires a new version and a fresh development fit. The routing algorithm sees only query text and scoped candidates. The scorer checks required-document recall and validates that every labeled fact occurs in its source.

Development and evaluation use disjoint document IDs. The development fit sweeps margins from 0 to 0.40 in 0.01 steps, excludes settings with over two percentage points of single-document recall loss, and ranks the remaining settings by ambiguous recall, false-LOCAL rate and single-document LOCAL rate, in that order. It takes the middle margin among tied settings.

The release gate compares 13 single-document and 13 multi-document pairs with two equivalent forms each. It requires at most two percentage points of single-document recall loss and a positive lower bound for both ambiguous recall gain and false-LOCAL reduction. The paired 95% intervals use 10,000 bootstrap draws with a fixed seed and keep overlapping required documents in the same cluster. A separate always-GLOBAL control distinguishes the focused named-document requirement from those metrics. A skipped empty scope, executed empty probes and verified negative preview matches are counted separately. Replay measures local retrieval behavior with synthetic documents and lexical embeddings.
